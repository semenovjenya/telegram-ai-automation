# ML Модуль: Предсказание вирусности постов

Экспериментальный ML pipeline для оценки количества репостов по признакам,
доступным до публикации поста. Готовая production-модель и подтвержденные
метрики в репозитории не поставляются: модель нужно переобучить на своих данных
и проверить на более новом временном отрезке.

## 📋 Описание

Этот модуль реализует ML алгоритмы для:
- **Предсказания количества репостов** поста до публикации
- **Сравнения разных моделей** (Random Forest, XGBoost, LightGBM)
- **Анализа важности признаков** для понимания, что делает пост вирусным
- **Автоматической обработки данных** из парсера каналов

## 🔧 Компоненты

### 1. Data Loader (`data_loader.py`)

Загружает и объединяет данные из:
- JSON файлов с топ постами (из `top_posts_analyzer.py`)
- CSV файлов с анализом канала (из `local_parser.py`)

**Основные функции:**
- `load_top_posts_json()` - загрузка постов
- `load_channel_analysis_csv()` - загрузка метрик канала
- `merge_data()` - объединение данных
- `prepare_features()` - базовая подготовка

### 2. Feature Engineering (`feature_engineering.py`)

Создает признаки из сырых данных:

**Временные признаки:**
- Час, день недели, месяц
- Циклические признаки (sin/cos для времени)
- Часть дня (утро/день/вечер/ночь)
- Выходные дни

**Признаки контента:**
- Типы контента (фото, видео, аудио, и т.д.)
- Комбинированные признаки
- Длина текста (логарифмированная)
- Категоризация длины текста

**Признаки результатов публикации:**
- Отношения просмотров, репостов и реакций могут создаваться для анализа данных
- Эти признаки исключаются из матрицы обучения, потому что до публикации они неизвестны

**Признаки канала:**
- Размер канала (логарифмированное количество подписчиков)
- Средний engagement rate
- Частота постинга
- Стабильность публикаций

**Интерактивные признаки:**
- Взаимодействие времени и типа контента
- Взаимодействие размера канала и типа контента

### 3. ML Models (`models.py`)

Реализует три типа моделей:

**Random Forest**
- Хорошо работает на малых данных
- Интерпретируемость через важность признаков
- Не требует масштабирования признаков

**XGBoost**
- Обычно лучше точность
- Быстрое обучение
- Хорошая работа с категориальными признаками

**LightGBM**
- Очень быстрое обучение
- Эффективно на больших данных
- Хорошая точность

### 4. Train Model (`train_model.py`)

Скрипт для обучения моделей:

```bash
# Основные параметры
--model          # Тип модели: random_forest, xgboost, lightgbm
--compare-all    # Сравнить все модели
--target         # Целевая переменная: forwards, views, replies, reactions
--validation-split  # Доля валидации (по умолчанию: 0.2)
--json-path      # Путь к JSON с постами
--csv-path       # Путь к CSV с анализом канала
```

**Что делает:**
1. Загружает данные
2. Создает признаки
3. Обучает модель
4. Вычисляет метрики (RMSE, MAE, R²)
5. Сохраняет модель и метрики
6. Выводит важность признаков

### 5. Predict (`predict.py`)

Скрипт для предсказаний:

```bash
# Основные параметры
--model-path     # Путь к модели (по умолчанию: последняя)
--json-path      # Путь к JSON с постами
--csv-path       # Путь к CSV с анализом канала
--output         # Путь для сохранения результатов
--top            # Показать топ-N постов (по умолчанию: 10)
```

**Что делает:**
1. Загружает обученную модель
2. Загружает новые данные
3. Создает признаки
4. Генерирует предсказания
5. Выводит топ постов по предсказанной вирусности
6. Сохраняет результаты в CSV

## 📊 Метрики модели

Модель оценивается по следующим метрикам:

- **RMSE** (Root Mean Squared Error) - средняя ошибка в единицах репостов
- **MAE** (Mean Absolute Error) - средняя абсолютная ошибка
- **R²** (Coefficient of Determination) - качество относительно константного прогноза; может быть отрицательным, чем ближе к 1, тем лучше

Числа из одного случайного разбиения не считаются подтвержденным качеством.
Для итоговой оценки используйте временной holdout: обучение на старых постах,
проверку на более новых.

## 🔍 Интерпретация результатов

### Важность признаков

После обучения модель выводит топ-10 самых важных признаков. Это помогает увидеть:

- **С какими признаками** связаны прогнозы модели
- **Какие гипотезы** стоит отдельно проверить экспериментом
- **Какие признаки** можно игнорировать

### Предсказания

Предсказания показывают **ожидаемое количество репостов** для каждого поста. Это позволяет:

- Найти потенциально вирусные посты
- Понять, какие посты не оправдают ожиданий
- Оптимизировать контент-стратегию

## ⚠️ Ограничения

1. **Объем данных**: фиксированного минимального числа постов, гарантирующего качество, нет. Качество нужно измерять на отдельном временном holdout.

2. **Исторические данные**: Модель обучается на исторических данных, поэтому изменения в поведении аудитории могут снизить точность.

3. **Внешние факторы**: Модель не учитывает:
   - Актуальность темы (тренды)
   - Внешние события
   - Качество контента (субъективная оценка)

4. **Время публикации**: Оптимальное время может меняться, требуется периодическое переобучение.

5. **Доступность признаков**: просмотры, репосты, реакции и производные от них показатели исключаются из модели как неизвестные до публикации.

6. **Формат модели**: файлы `.pkl` могут выполнять код при загрузке. CLI принимает только модели, созданные локально и находящиеся в `parser_local/ML/models`; не используйте скачанные артефакты.

## 🐛 Решение проблем

### Ошибка "Не найдено данных"

Проверьте:
- Есть ли JSON файлы в `../Logs/`
- Есть ли CSV файлы анализа канала в `../Logs/`
- Правильно ли указаны пути к файлам

### Ошибка "Мало данных для обучения"

Решение:
- Соберите больше постов (запустите `top_posts_analyzer.py` с большим лимитом)
- Уменьшите `validation_split` до 0.1

### Модель показывает плохие результаты

Возможные причины:
- Мало данных для обучения (< 50 постов)
- Данные не репрезентативны
- Признаки не информативны

Решение:
- Соберите больше данных
- Проверьте важность признаков
- Попробуйте другую модель
